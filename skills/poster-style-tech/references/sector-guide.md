# 科技专项决策

## 先确定产品类型

| 类型 | 需要校准 | 有效的表达方式 |
| --- | --- | --- |
| 硬件 | 外形比例、按键、接口、屏幕与材质 | 展示真实结构、尺度或使用场景 |
| 软件、AI 工具 | 界面布局、功能状态与真实输出 | 一个任务的前后流程或可见成果 |
| SaaS | 目标用户、已上线功能与核心操作 | 明确的一项价值配一张真实界面 |
| 技术活动 | 名称、时间、地点或线上入口 | 用信息结构引导报名或了解详情 |

参考里的芯片、机械臂或数据线不是必需品。先给出一个具体收益，例如“把分散资料整理成可检索工作区”，再选择符合该功能的视觉比喻。

## 真实 UI 与概念示意

用户提供截图且要求准确时，优先合成真实截图，生成环境、背景或设备框；不要重画可点击控件和密集界面文字。屏幕透视变换也必须维持结构与可读性。

可为尚未实现的想法画概念界面，但在交付说明和容易被误认为实测的画面中标明“概念示意”。不要让虚构功能出现在“已上线”卖点列表。界面素材若有用户明确指出的隐私内容，先做遮挡或使用用户同意的示例数据。

## 规格与证明

速度、延迟、容量、精度、跑分、兼容平台、价格、发布日期和认证均为事实变量。没有资料时直接省略。不能用装饰性的 99.9%、倍速或实时曲线冒充实测表现。

比较画面需有可核对的比较对象与条件，否则改用流程或场景表达。原理图、结构爆炸图会暗示真实技术结构，不清楚内部结构时用抽象分层说明，不画成产品拆解事实。

## 科技专项验收

- 不读小字能否知道产品类别和一项具体价值？
- 真实硬件结构与 UI 是否被改动？
- 概念图与实际上线功能是否清楚区分？
- 参数、兼容性和性能证明是否有来源资料？
- 科技装饰是否抢走了产品与标题的视觉中心？
